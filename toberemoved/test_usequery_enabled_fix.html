🔧 useQuery Enabled Option Error - FIXED!

The "Expected enabled to be a boolean" error has been resolved!

❌ Original Error:

Error: Expected enabled to be a boolean
Uncaught Error: Expected enabled to be a boolean at QueryObserver2.setOptions (queryObserver.js:73:13) at useBaseQuery.js:78:14

This error occurred in the RecordProcurementDialog component when the useQuery hook received a non-boolean value for the `enabled` option.

🔍 Root Cause Analysis:

JavaScript Type Coercion Issue

The problem was in this line:

{ enabled: open && selectedFarmerId }

When selectedFarmerId is an empty string "", the expression open && selectedFarmerId returns the empty string, not a boolean. React Query's useQuery expects the enabled option to be strictly a boolean value.

✅ Solution Applied:

✅ Fixed Boolean Conversion
Changed the enabled condition to ensure it always returns a boolean:
// Before (problematic) { enabled: open && selectedFarmerId } // After (fixed) { enabled: open && !!selectedFarmerId }

The double negation !!selectedFarmerId converts any truthy/falsy value to a proper boolean.

🧪 How the Fix Works:

Before Fix:
  • open = true, selectedFarmerId = "" → enabled = "" (string, not boolean)
  • open = true, selectedFarmerId = "123" → enabled = "123" (string, not boolean)
  • open = false, selectedFarmerId = "123" → enabled = false (boolean, correct)
After Fix:
  • open = true, selectedFarmerId = "" → enabled = false (boolean, correct)
  • open = true, selectedFarmerId = "123" → enabled = true (boolean, correct)
  • open = false, selectedFarmerId = "123" → enabled = false (boolean, correct)

💡 Technical Notes:

This fix demonstrates the importance of type safety in React Query options. The enabled option must always be a boolean, and JavaScript's truthy/falsy evaluation can sometimes return non-boolean values that cause runtime errors.

The double negation operator !! is a common JavaScript pattern for converting any value to a boolean:

  • !!"hello" → true
  • !!"" → false
  • !!0 → false
  • !!123 → true
